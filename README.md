# KV 卸载与实例规模计算器（简化版）

单页静态计算器，无后端、数据不出浏览器。回答三个问题：

1. **可承载实例数**——选定模型与精度后，全部计算节点能跑几个实例（每实例所需节点数一并给出）；
2. **单 token KV 大小**——按模型注意力架构（GQA / MLA / 混合线性）× KV 量化精度计算；
3. **KV 卸载设备的容量与读带宽**——按请求到达率 × 单请求 KV × 保留窗口计算。

15 款模型开源模型（架构参数解析自各模型 HuggingFace `config.json` 与模型卡片）：
Qwen3.8 系列（2.4T-A95B / **27B** / Flash-Next）、GLM-5.x、DeepSeek-V4.1-Flash、Kimi-K3 / K3.1-Pro、MiMo-V2.6、HunYuan Hy3 / Hy4-preview、MiniMax-M3 / M3.1-Flash。

> Qwen3.8-27B（`Qwen/Qwen3.8-27B`）：64 层 **混合线性注意力**（16 层全注意力 + 48 层线性，每 4 层插 1 层全注意力），hidden 5120、24 头 / 4 KV 头、head_dim 256，BF16 原生、27.8B **稠密**参数、上下文 262,144。→ 单 token KV 32,768 元素（65.5 KB @BF16）、每序列线性状态 38.93M 元素（155.7 MB @FP32）。

## 计算口径

独立估算链（单页无后端，全部计算在浏览器内完成）：

```
每实例节点数 = ⌈(权重 + 在途×单请求KV×KVH) ÷ (GPU数 × 显存 × 90%)⌉（KVH=0.5：仅一半在途 KV 常驻 HBM，另一半常驻卸载设备，v1.6）
                再沿节点数向上取最小合法并行网格：TP 须整除注意力头数与 hidden 维，
                PP 须整除层数（节点内 TP 优先；如 Qwen3.8-2.4T 的 92 层 ⇒ 3/5/6/7 节点不可行，4 节点 TP8×PP4 起）
实例数       = ⌊节点总数 ÷ 每实例节点数⌋
单请求 KV    = 上下文长度 × 单token KV + 线性注意力固定状态（FP32）
到达率       = 有效并发 ÷ (prefill时长 + 输出长÷tps)　【有效并发 = min(需求侧集群总并发, 集群上限)；上限：非 PD = 实例数×每实例可持续流，PD = D 池可服务流】
写带宽       = 到达率 × 单请求KV          读带宽 = 写带宽 × 1.0
容量(主KPI) = 写带宽 × 保留窗口 × 1.2（保留窗口制口径）
容量(工作集)= 有效并发 × 单请求KV × 1.2（在途工作集口径，明细并列）
```


固定假设（页脚有完整释义）：MFU 50%、显存利用率 90%、冗余 1.2、读放大 1.0、去重率 0；DSA 稀疏注意力索引状态按 KV 同精度计入单 token KV。
「单 GPU 算力」填**矩阵乘实际执行精度的稠密（非稀疏）峰值**：BF16/FP16 权重按 BF16 档、FP8 权重按 FP8 档、
INT4（weight-only 量化，实际以 BF16 算力执行）按 BF16 档；默认 2.0 PF = H100/H200 的 FP8 稠密峰值（1979 TFLOPS）。
PD 分离按「**每个实例各持一份完整权重**」建模：全系统权重占用 = 实例总数 × 单份（P、D 实例互不共享），显存按每实例 1 份核算。

**TP 复制**：TP 超过 KV 头数时 KV 在卡间复制（GQA ⌈TP/KV头⌉ 份，MLA 按 TP 份整份复制，
vLLM/SGLang 标准行为），显存需求与水位按复制计，卸载池仍存单份。

**风险告警（v1.9.1 更名，仅列 ⚠/✗ 项，通过项折叠在「校核通过项」内）**：单请求 prefill vs TTFT 目标；prefill 算力占用（到达率×时长）与
decode 吞吐占用（÷参考聚合 dec_agg=350 tok/s/卡×实例GPU数×算力缩放）分列，并给出"算力可持续在途"；
KV 水位阈值 70%（工程经验阈值）。

## 闪存磨损（v1.9）
- 输入：DWPD（默认 1）、期待寿命（**默认 3 年**；反推磨损保底容量并与保留窗口取大，留空则不参与容量推算）、忙/闲时段（默认 **08–18** 忙 100%、其余闲 20% → 24h 加权 ≈53%；改成 00–24 即全天忙口径）。
- 日均写入 = 峰值写带宽 × 86400 × 加权系数；**磨损寿命(年) = DWPD × 选型容量 × 5 ÷ 日均写入**（DWPD 以 5 年保修期定义，分子含 5 年基准；等效日覆盖次数 = 日均写入 ÷ 选型容量）。
- 期待寿命反推磨损保底容量 = 日均写入 × 期待年 ÷ (DWPD × 5)；**仅在填写时计算**，最终容量取 max(保留窗口容量, 磨损保底容量)，KPI 标注“磨损保底主导”。
- **窗口 ⇄ 寿命的容量闭环（v1.9.1）**：输入的 KV 保留窗口只是容量下限；若「期待寿命」反推的磨损保底更高，选型容量被抬到窗口之上，多出的容量意味着**实际可保留更长的 KV 窗口**（等效保留窗口 = 选型容量 ÷（写带宽 × 1.2），明细中显示）；也可视为容量冗余。反向耦合同样成立：调大窗口 → 容量变大 → 覆盖次数变密 → 寿命变短。
- **并行形状代价（v1.9.14，按 NVLink/NVL72 带宽标定，系数固定不可调）**：形状排序不再凭感觉。TP 代价按等效 all-reduce 带宽算：`f = 2×跨机台数 ÷ TP`（ring 上跨机链路占比），域内跨 tray 走 NVLink（0.9 折），跨出 NVLink 域走 IB（800 Gb/s≈100 GB/s/卡），等效倍数 `1 ÷ ((1−f) + f×(100/900))`——TP16 跨 2 机 ≈×1.13、TP32 跨 4 机 ≈×1.20；PP 气泡按微批 M≈8 的 `M/(M+PP−1)` 折算，每级 ×(1+1/8)（PP4→1.5、PP8→2.0）。域大小按型号判定：B100/B200/B300 → 72 卡（NVL72 整机柜）、其余 → 8 卡（单机 NVLink、跨机即 IB）。代价只乘在理想 prefill 时长上，用于选形状与 TTFT 判断，不改 λ/服务时长公式；默认 24/8 仍是 **3×8 / TP16×PP4（形状代价 ×1.69，有效 prefill 1007 ms）**。
- **decode 改带宽口径（v1.9.13，2026-11）**：decode 是**访存受限**，旧「350 tok/s/卡 × 算力缩放」锚值停用。新增输入「单卡 HBM 带宽（TB/s）」，选 GPU 型号自动带出（H100 3.35 / H200 4.8 / B200 8.0 / A100 2.0 / H20 4.0）；每实例可承载流 = ⌊(实例卡数 × 单卡带宽 ÷ 目标 tps − **激活权重** GB) ÷ (每流在驻 KV)⌋，其中激活权重 = 激活参数 × 权重大小（MoE 只读激活专家），每流在驻 KV = 单请求 KV × TP 复制 × 50% 常驻。默认 24/8 时 D 上限由 97 → **183**（仍非瓶颈，P 池 32 是受限项）；tps 80→160 时降到 84；HBM 换 8 TB/s 升到 458；上下文/ KV 精度按同一公式联动。
- **在途上限更显眼（v1.9.12）**：除明细行外，顶部小标新增第 4 项「**X 条在途上限（受限项）**」，PD 配比提示行也直接带出「算力上限 X 条在途（受限项 P 池 prefill / D 池 decode / D 池显存）」——点完「按算力均衡推荐」就能在配比框下方看到当前配比能挂多少在途。
- **算力上限展示（v1.9.11）**：明细「算力上限（可持续在途）/ 集群」直接给出**当前配比最多能挂多少条在途请求**，并拆成三项取 min 说明受限项——`P 池 prefill`（P 供给×输出长÷tps）、`D decode`（D 实例数×⌊decode 聚合÷tps⌋）、`D 显存`（D 实例数×可驻序列数）；输入框提示同步显示该上限；需求超上限时告警给出“超出部分不产生吞吐”，推荐配比行也会给出**推荐配比自身的**上限条数。默认 24/8：上限 32 条（P 池 32 为受限项，D decode 97、D 显存 251）。
- **实例形状排序（v1.9.9）**：P 池实例粒度不只按“用满节点”选，还按 `用满节点 > PP≤8 > 满足 TTFT > prefill 更快 > 机内 TP` 排序——PP>8 的深流水（如 26 节点 TP8×PP26）不再被推荐；吞吐与形状不可兼得时，优先保住用满节点数（≤5% 余量内再优先 TTFT）。GLM-5.3 默认因此由「1 实例 × 26 节点（TP8×PP26）」改为「13 实例 × 2 节点（TP8×PP2）」，TTFT 678 ms 会给出超目标告警。
- **并发默认值反解（v1.9.8）**：输入框默认不再固定 40，而是按「P、D 两池同时打满」自洽反解——取 `C = P 供给 × 输出长 ÷ tps`（打满 prefill）且 `D 池可服务流 ≥ C`（decode 也不闲置）的点，并在该 C 下取 λ 最大的 P/D 配比。**切换模型会自动重算配比与并发默认值**；手动改过并发后不再自动覆盖（切 PD/换模型会重置）。默认 32 节点 + 2.4T-A95B：并发 32、P24/D8、λ 5.03、936 TB；27B：并发 103、P23/D9、λ 16.1；Flash-Next：并发 233、P13/D19、λ 36.4。
- **需求改为集群总并发（v1.9.7）**：输入框为「峰值并发请求数（集群总）」——整个集群所有实例合计的并发数。PD 下 D 池规模由它决定（够服务即可），剩余节点全部给 P；因此改该输入会**改变 P/D 配比**并连带改变容量/带宽/TTFT。非 PD 下按实例数平摊为每实例并发，集群上限 = 实例数 × 每实例可持续流。
- **在途 = 需求参数（v1.9.6）**：输入框更名为「峰值并发请求数」，明示为业务口径；硬件只决定上限（算力可持续在流、显存可驻在流、decode 可承载流），实际在流 = min(需求, 上限)。同一套 32 卡在需求 10 / 40 / 97+ 下容量分别为 585 / 941.5 / 941.5 TB（PD 24/8），说明改该输入是在改负载而非硬件。明细行更名为「算力上限（可持续在流）」并并列给出需求与上限。
- **权重份数口径（v1.9.5）**：PD 下不再是「双副本」，而是**每个实例各持一份**——P 3 实例 + D 1 实例 = 4 份权重；明细「模型权重」行给出「P x + D y = n 份 × 单份」与合计，显存/实例核算仍按每实例 1 份（原先把 Weff 写死 ×2 既误导显示、又让单份权重语义失真，已改为单份）。
- **可持续口径（v1.9.4）**：非 PD 与 PD 统一按「有效在流 = min(目标在途, 算力可持续在流)」计算吞吐；目标在流超出算力时只降低在流（并告警），不再用目标在流虚增吞吐。默认 32 节点 + Qwen3.8-2.4T-A95B 下非 PD 容量由 4,281 TB（目标在流口径）降为 **1,177 TB**（λ 6.3 req/s）。
- **自查修复（v1.9.3）**：
  1. 推荐配比的 D 侧供给原按 `350×算力/输出长` 高估（未受在途/显存上限约束），导致“声称 λ”高于应用后真值（如 nout=2048 时 3.83 vs 1.56）。现与主算法同式：`在流=min(目标在途, decode 算力可承载流, 显存可驻流) × tps ÷ 输出长`。
  2. 推荐改为**按实例数枚举**（`1..⌊节点/实例⌋` 组合，取 λ 最大且用满节点者），消除“按节点取整”的浪费（如 20 节点原推荐 8/12 实际只用 16）。
  3. 容量/日写入/寿命/等效窗口等明细行原以**非 PD 单池网格**为门控，PD 模式下单池网格不存在时会错误显示“不可部署”；改用 `deployOk = 单池网格 || 两池成型且 P+D≤总节点且 λ>0`。
  4. PD 模式下页脚“本例”推导曾混用非 PD 的实例数/复制数/decode 聚合；已改为双池口径。
  5. 磨损寿命告警原被“非 PD 显存预算>0”门控，PD 下可能漏报；现独立成条，KV 水位告警按池取数（PD 用 D 池）。
  6. 非法配比（P=0 / D=0 / 节点不足以形成实例 / P+D>总节点）现显示容量 “–” 并给出具体原因，不再输出 0 TB 的伪数值。
  7. 忙时段结束 ≤ 开始（跨零点班次）给出告警，说明按 0 小时忙计。
  8. 推荐结果每次 `calc()` 只计算一次（原为 3 次）；1024 节点下整页重算约 7 ms。
- **PD 分离双池模型（v1.9.2）**：PD 勾选后 P/D 节点数可输入；「按算力均衡推荐」穷举分配使 λ=min(P 供给，D 供给) 最大（P 供给=节点算力×MFU÷prefill FLOPs，D 供给=350 tok/s/卡×缩放÷输出长度）；两池各自求最小合法 TP×PP 实例（P 仅权重，D 含在途 KV 50% 常驻），容量/带宽/日写入/寿命全部由均衡后 λ 推导；明细展示两池利用率与瓶颈，超配/闲置有告警。权重按「每实例 1 份」计：P 3 + D 1 实例 ⇒ 全系统 4 份权重（明细「模型权重」行给出份数与合计）。
- **容量与忙闲无关（v1.9.1）**：保留窗口容量 = 写带宽 × 窗口 × 1.2，**始终按窗口内峰值满载全量保留**（哪怕是最忙的 2 小时），不受忙闲时段影响。忙闲分时负荷只作用于**日均写入量**（= 写带宽 × 86400 × w），进而影响磨损寿命与期待寿命反推容量。在途工作集口径同样与忙闲无关（在途请求数是瞬时量）。
- 容量变小会加快磨损：等效日覆盖次数 = 日均写入 ÷ 选型容量。未计 SSD 写放大与读磨损（实际寿命只会更短）。
- 风险标红：寿命 < 风险线（填写时=期待寿命，留空时=3 年）→ KPI 副标 / 明细 / 风险告警三处红字加粗。

## 官方缓存语义与精度默认（v1.3 / v1.4，重要）
- **DeepSeek-V4.1-1017**（官方 `inference/model.py`）：KV 仅 4 个源层拥有且**池化压缩**（compress_ratio 2/2/2/1 → 每 token 2.5 条 512 维 latent，rope 内含于 512）；indexer 为 4 份源层共享的 128 维单键（32 个 index 头是查询侧概念，不复制键）；每层 128×512 FP8 滑窗环（含 3 DSpark draft）按每序列常量计。合计 1,600 元素/token + 2.82M/序列（v1.3 前误按 35,072 元素/token，高估 21.9×）。
- **DeepSeek-V4-Flash**（原列作 DeepSeek-V4-Flash-0731 快照，现链接并取数于官方主仓库 deepseek-ai/DeepSeek-V4-Flash，架构与快照完全一致）：21 层 ratio=4 + 20 层 ratio=128 交错池化（5.41 条×512/token + 5.25 条×128 indexer），46 层滑窗。
- **Kimi-K3 / K3.1-Pro**：69 KDA 线性层 + 24 MLA 全注意力层混合；MLA 576/token；KDA 循环态 116.2M 元素/序列（FP32）。
- 对标 [kvcache.ai KV Cache Calculator](https://kvcache.ai/tools/kv-cache-size-calculator/)：其 V4.1 "890 B/token @8K" 为官方 FP4 载荷含量化 scale；本工具 FP4 档 = 800 B（不含 scale）+ 滑窗摊销，结构口径一致。
- **精度默认随模型**：切换模型时权重精度置为原生发布精度（safetensors dtype 桶 + quantization_config 判定，`detect_wdt`）；KV 默认：FP8/FP4 权重模型 → FP8，BF16 模型 → BF16。FP8 注意力+FP4 专家的混合检查点在 FP4 档按 0.5 B/参数统计，低估注意力部分 10~25%。
- **dec_agg**：decode 聚合吞吐参考 = 350 tok/s/卡 × 实例 GPU 数 × (算力÷2.0)（"32 卡×350=11,200 tok/s" 外推假设，务必实测替换）。
- **v1.5 全模型对标 kvcache.ai**：DSA/MSA 索引键统一为 **MQA 单键 × 拥有层**（GLM-5.2/5.3、Hy4 → 21×128=2,688/token；MiniMax-M3 → 57×128=7,296；M3.1 → 60×128=7,680；Qwen3.8-Flash-Next → 12×128÷4=384，估计值）；规则以 DeepSeek-V3.2 实测口径验证（61 层全索引 → 42,944 元素/token）。MiMo-V2.6 = **9(10) 全层 + 39(60) 滑窗层**（窗口 8头×(192+128)×128 每序列快照，随 KV 精度）。GLM/M3 两家精确一致；V4 系差异仅为 draft 层窗口开关。

- **自定义 GPU 参数（v1.9.1）**：仅在**本次页面会话内**记住「自定义」下填写的算力/显存——切到具体型号再切回「自定义」会恢复该设定；**不做持久化**，刷新页面一律回到默认（自定义 1.4 PF FP8 稠密 / 144 GB，按当前权重精度折算显示），保证每次刷新状态一致。全文件无外部依赖、无 localStorage / 无后端。
