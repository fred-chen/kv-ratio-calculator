    固定假设（不可调，均已计入公式）

    算力基准："单 GPU 算力"填矩阵乘实际执行精度的稠密（非稀疏）峰值——BF16 权重按 BF16 档、FP8 权重按 FP8 档、INT4（weight-only，主流方案，反量化后用 BF16 算）按 BF16 档；厂商标称的"稀疏翻倍"数字不可用。默认 2.0 PF = H100/H200 的 FP8 稠密峰值（1979 TFLOPS）。
    算力有效利用率 MFU = 50%：标称 PFLOPS 是峰值，推理中注意力/通信/访存开销后实际约一半能被有效计算利用，业界大模型推理常用取值。
    显存利用率 = 90%：单卡显存中可安全用于"权重 + KV"的比例，余 10% 给激活值、框架缓存与碎片。
    容量冗余系数 = 1.2：卸载设备容量按需求上浮 20%，覆盖元数据、EC 对齐与突发。
    带宽按峰值、容量可按忙闲折算：写/读带宽决定「忙时瞬时吞吐能力」，必须按峰值（忙时 100%）配置，不做忙闲折减；只有容量（保留窗口能装多少）可按 24h 加权折算。
    带宽合计怎么算（读写并发，v1.9）：KV 写入（新 token 落盘）与 KV 读取（历史命中回源）在服务期同时发生。若读写共用物理通道（本地 NVMe、单套存储池、单端口网络——PCIe 与介质通道读写共享），总吞吐约为单向峰值，选型应按写+读合计；若读写走物理独立路径（写本地盘 + 读远端池、或全双工网络上下行独立），则按 max(写, 读) 即可。明细同时给出合计与 max 两个数，勿把两者相加后再拿去比"单盘顺序读带宽"——那是单向口径。
    读放大系数 = 1.0：假设每块 KV 在保留窗口内平均被完整读回一次（命中一次）；重访密集场景可按 2–3 倍上浮。
    DSA 稀疏注意力索引已计入：DeepSeek-V4.1 / GLM-5.x / Hy4 / Qwen3.8-Flash-Next 的索引状态（config 的 index_* 字段）按每 token 缓存、与 KV 同精度计入单 token KV 与卸载量——稀疏注意力省的是算力，不省这份存储。
    GPU 型号库（v1.8，2026-11 联网核实）：NVIDIA A 系（A100/A800：BF16 稠密 312 TF，无 FP8）；H 系（H20 0.296、H800/H100/H200 1.979 PF FP8 稠密，data sheet 头条值为稀疏口径需÷2）；B 系（B100 3.5、B200/B300 4.5 PF FP8 稠密，288/192GB）；摩尔线程 S4000（BF16 0.128，无 FP8）/S5000（FP8 1.0 PF、80GB）；海光 BW1000（FP16 0.48，官方未直接公布）/BW1100（FP8≈0.26、144GB HBM3e，官方未公布算力、按公开部署配置表口径）。选型号后按当前权重精度自动填对应档：FP8 权重→FP8 档、BF16/FP16 权重→BF16 档、INT4/NVFP4 weight-only→BF16 档（反量化后由 BF16 矩阵乘执行）。算力必须与权重精度对应：若所选 GPU 无该精度的 Tensor 核心（A100/A800、MTT S4000、海光 BW1000 均无 FP8），则按同级 INT8 稠密折算等效（INT8 稠密 ≈ 2×BF16 稠密：A100 0.624、S4000 0.256、BW1000 0.96 PF），算力框旁以「INT8 稠密（等效 FP8）」标注；自定义卡以 FP8 稠密峰值为基准，切 BF16 权重时自动 ÷2 折算显示。手动改动即视为自定义。
    忙闲分时加权与闪存磨损（v1.9）：24h 负荷系数 w =（忙窗小时×忙时% + 闲窗小时×闲时%）÷24，缺省 08–18 时忙 100%、其余闲 20%（w≈53%）。磨损寿命(年) = DWPD × 容量 × 5 ÷ 日均写入（DWPD 按 5 年保修期定义，故分子含 5 年基准；日均写入 = 峰值写带宽 × 86400 × w）；期待寿命反推保底容量 = 日均写入 × 年 ÷ (DWPD × 5)，最终选型容量取 max(保留窗口, 磨损保底)。PD 分离双池模型（v1.9.2）：勾选 PD 分离后出现「PD 池节点配比」——P 节点只做 prefill（产出 KV 写入存储），D 节点只做 decode（命中时从存储读回）。两池节点数可直接输入，「按算力均衡推荐」以需求侧集群总并发 C 为约束：D 池只需够服务 C（可服务流 = min(C, decode 带宽上限 = 实例卡数×单卡HBM带宽÷tps 扣激活权重后的余量 ÷ 每流在驻KV, 显存可驻 = (显存 − 权重×实例数) ÷ 单序列常驻 KV)），其余节点全部给 P（P 供给 = 节点数×算力×MFU ÷ 单请求 prefill FLOPs）；枚举 D 节点数取 λ = min(D 并发×tps÷输出长, P 供给) 最大者。因此增大需求并发会把节点从 P 挪到 D，反之释放给 P；实例粒度在并列时 P 取更大实例（prefill 更快、TTFT 更低）。系统吞吐、KV 写带宽、容量、日写入、磨损寿命均由该 λ 推导；明细给出两池利用率与瓶颈，告警提示 P/D 配比失衡或节点超配/闲置。注意：每个实例各持一份完整权重，P、D 实例之间不共享——全系统权重占用 = 实例总数 × 单份（如 P 3 + D 1 = 4 份），显存按每实例 1 份核算；单请求服务时长按 prefill + decode 计，未含 P→D 的 KV 传输与两池排队，故尾延迟（TTFT/TPOT）需以实测校正。
    窗口 ⇄ 寿命的容量闭环（v1.9.1）：输入的「KV 保留窗口」只是容量下限；若「期待寿命」反推的磨损保底更高，选型容量被抬到窗口之上，此时多出的容量意味着实际可保留更长的 KV 窗口——等效保留窗口 = 选型容量 ÷（写带宽 × 1.2），已在明细显示；也可视为容量冗余。反向耦合同样成立：调大窗口 → 容量变大 → 覆盖次数变密 → 寿命变短。
    容量与忙闲无关（v1.9.1）：容量估算永远按给定的 KV 保留窗口全量保留——即按最忙时段（窗口内满载）的写入速率 × 窗口 × 1.2 计，不受忙闲时段长短或闲时负荷影响。忙闲分时负荷只作用于日写入量（日均写入 = 峰值写带宽 × 86400 × w），进而影响磨损寿命与「期待寿命反推保底容量」。因此改忙时段只会改变寿命，不会改变容量 KPI（除非触发磨损保底主导）。在途工作集口径与忙闲无关（在途请求数是瞬时量）。未计 SSD 写放大与读磨损，实际寿命偏保守。「期待寿命」留空即不参与容量推算（容量只按保留窗口）；一旦填写，则额外反推磨损保底容量并与保留窗口取大，最终容量取 max。无论留空与否，磨损寿命低于风险线（填写时为期待寿命，留空时为 3 年）即以红字标风险。
    在途 KV 常驻 HBM 比例 = 50%（v1.6）：本工具场景即 KV 卸载，不要求全部在途 KV 驻留 HBM——显存下限、TP×PP 网格可行性与 KV 水位均只按一半在途 KV 常驻（复制后 ×50%）核算，另一半常驻卸载设备、按页脚『写带宽×保留窗口 / 在途工作集』两口径另行计量。此比例写在代码常量 KVH 中。
    KV 显存复制系数：张量并行（TP）切分注意力时，每个 TP 秩至少持有 1 个 KV 头，TP 超过 KV 头数即产生整头复制（vLLM/SGLang 标准行为）；GQA 为 ⌈TP÷KV头数⌉ 份、MLA 的单条 latent 不切分、按 TP 份复制——显存需求与水位据此放大，卸载池仍存单份。
    PD 双池口径（v1.9.10）：每个实例各持一份完整权重（P、D 实例之间不共享，全系统权重 = 实例总数 × 单份，本例份数见明细"模型权重"行）——显存按每实例 1 份核算；吞吐取保守锚（prefill MFU 50%、decode 走 HBM 带宽口径），池间隔离后实际值有望更好，实际 tps/λ 上限可优于本页结果。
    并行网格偏好：TP ≤ 256 卡（1 个 NV 域）、PP ≤ 8；域内跨节点 TP 属正常形态（NVLink 交换），超出 NV 域才警示并计入跨域 RDMA 代价；不搜索 EP/DP 拓扑（K3 类奇数层 MLA 模型可能因此给出偏大网格）。
    上下文口径（v1.9.17）：可选单值（全部请求同一长度）或区间（正态分布）——区间取 μ=(最小+最大)/2、σ=(最大−最小)/6（端点视为 μ∓3σ）；单请求 KV 与写入带宽按 μ 计，prefill 计算量按 E[ctx²]=μ²+σ² 计（注意力项对长度是二次的）。实际分布若偏长尾（非正态），请把最大值取到 P95~P99 再评估。
    超节点拓扑与并行形状代价（v1.9.16，系数固定不可调）：1 个 NV 域 = 256 卡（32 节点 × 8 卡；64 节点 = 2 个 NV 域，依次类推）；域内跨节点仍走 NVLink 交换，跨域走 3.2 Tbps RDMA（≈400 GB/s，对 NVLink 900 GB/s/向 约 2.25×）。 TP 上限 = 256 卡（= 1 个 NV 域、32 节点），同一实例尺寸会把 TP16×PP4 / TP32×PP2 / TP64×PP1 等多套合法并行都纳入比较。 TP 代价：ring 上跨机链路占比 f=2×跨机台数÷TP（每过一台机 2 条）；域内单跳 ≈1.11×、跨域单跳 ≈2.25×，得 all-reduce 耗时倍数，再按「通信占 prefill 的 35%」阻尼（MFU 50% 已含平均通信停顿）：倍数 = 1 + 0.35×(耗时倍数−1)。 PP 代价：流水气泡只对 ≥2 级生效，微批 M≈8 时每多一级 ×(1+1/8)。 该代价用于：① 池内选形状；② P 有效供给 = 理想供给 ÷ 倍数、D 有效流 = 物理流 ÷ 倍数；③ 系统 λ 与 PD 配比推荐都按有效值比较。注意：TP 超过 KV 头数会导致 KV 复制系数 rep=⌈TP÷KV头数⌉ 增大（本例 TP64 时 rep=16，D 池显存可驻数因此降到 62 条）。
    KV 水位阈值 70%：超过即建议扩容或降压在途（工程经验阈值）。
    容量单位口径：本页面 GB/TB 均为 10⁹/10¹² 字节；厂商标称显存若按 GiB 计，结果偏保守约 7%。
    索引器键缓存统一为 MQA 单键（v1.5）：DSA/MSA 稀疏注意力的 index 键缓存按"拥有层 × 128 维单键"计（32/64 个 index 头是查询侧概念，不复制键；拥有层数取 config 的 indexer_types(full)/sparse_attention_freq/层列表），DeepSeek-V3.2 实测口径验证（61 层全索引 → 35,136+7,808=42,944 元素/token）。MiMo-V2.6 为混合滑窗架构：9(10) 全层 + 39(60) 个 128-token 窗口层，窗口缓存转每序列快照。
    DeepSeek-V4 系 / Kimi-K3 按官方参考实现建模（v1.4）：V4.1-1017 与 V4-Flash 的全局 KV 是池化压缩存储（每 1/ratio token 一条 512 维 latent：V4.1 → 2.5 条/token，V4-Flash → 5.41 条/token）；indexer 键缓存为源层共享的 128 维单键（非 32/64 头各存）；滑窗 128×512/层 FP8 按每序列常量计入明细。Kimi-K3/K3.1 为 69 KDA 线性 + 24 MLA 混合（循环态 116.2M 元素/序列，FP32）。结构口径与 kvcache.ai 计算器一致；其 890 B/token 为官方 FP4 载荷含量化 scale（本工具选 FP4 档 ≈ 862 B，+scale ≈ 890 B）。V4 系 prefill 二次项仍按稠密上界（DSA 实际为稀疏 topk 打分，TTFT 属保守值）。
    精度默认随模型（v1.3）：权重精度默认值取自模型原生发布精度（按 HF safetensors dtype 桶与 quantization_config 判定，见模型表"原生权重"列）；KV 默认：原生 FP8 或 FP4 → FP8，BF16 → BF16。混合精度检查点（FP8 注意力 + FP4 专家，如 V4 系 / Kimi / MiMo / M3.1）在 FP4 档按全体 0.5 B/参数计，较真值低估 FP8 注意力部分约 10～25%，需保守可手动切 FP8 档。
    前缀去重率 = 0：保守口径——每个请求独立存储自己的 KV，不依赖跨请求前缀共享收益。
    线性注意力状态按 FP32：混合模型的循环状态（如 Gated DeltaNet 的矩阵状态）对量化敏感，即使 KV 选了 FP8/INT4，该部分仍按 4 B/元素计。
    Prefill 算力 2×P_active×ctx + L_full×(d_model+d_kv)×ctx²：一次项为全部激活参数的矩阵乘，二次项为全注意力层的 QKᵀV；decode 算力 2×P_active FLOPs/token。注意：二次项为工程简化式（Q 侧宽度取 hidden、且不乘标准 2×MAC 因子），较教科书完整式约低 2×，TTFT 校核相应偏乐观。

    计算链

    每实例节点数 = ⌈(权重 + 在途×单请求KV) ÷ (GPU数×显存×90%)⌉，随后沿节点数向上搜索最小合法并行网格：TP（可跨节点）须同时整除注意力头数与 hidden 维，PP 须整除层数（vLLM/SGLang 均要求整除；TP 超过 KV 头数时 KV 头复制存放） → 实例数 = ⌊节点总数 ÷ 每实例节点数⌋； 到达率 = 有效并发 ÷ 单请求服务时长（有效并发 = min(峰值并发（集群总）, 集群上限)；非 PD 的集群上限 = 实例数 × 每实例可持续流 ⌊min(服务时长÷prefill 时长, decode 聚合÷每流 tps)⌋；PD 的集群上限 = D 池可服务流 min(decode 算力, 显存可驻)；非 PD 与 PD 统一按可持续口径，需求超出上限只拉低并发、不虚增吞吐）。在途/并发是需求参数——由业务峰值并发请求数给定；硬件只决定上限（算力可持续在流、显存可驻在流、decode 可承载流），二者取 min 后才是实际在流。因此同一套硬件在不同业务峰值下给出不同容量（例：32 卡 PD 24/8，需求 10 → 585 TB，需求 40 → 941.5 TB，需求 ≥97 后饱和）；调「峰值并发请求数」是在改负载，不是在改硬件。写带宽 = 到达率×单请求KV；容量（双口径并列）= 保留窗口制：写带宽×窗口×1.2（页面主 KPI，选型决策）｜ 在途工作集制：在途实例×在途×单请求KV×1.2（明细行，不假设保留期）；显存足迹按 TP 复制系数放大（GQA：⌈TP/KV头⌉，MLA：TP）。
