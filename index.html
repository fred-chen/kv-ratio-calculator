    固定假设（不可调，均已计入公式）

    算力基准："单 GPU 算力"填矩阵乘实际执行精度的稠密（非稀疏）峰值——BF16 权重按 BF16 档、FP8 权重按 FP8 档、INT4（weight-only，主流方案，反量化后用 BF16 算）按 BF16 档；厂商标称的"稀疏翻倍"数字不可用。默认 2.0 PF = H100/H200 的 FP8 稠密峰值（1979 TFLOPS）。
    算力有效利用率 MFU = 50%：标称 PFLOPS 是峰值，推理中注意力/通信/访存开销后实际约一半能被有效计算利用，业界大模型推理常用取值。
    显存利用率 = 90%：单卡显存中可安全用于"权重 + KV"的比例，余 10% 给激活值、框架缓存与碎片。
    容量冗余系数 = 1.2：卸载设备容量按需求上浮 20%，覆盖元数据、EC 对齐与突发。
    读放大系数 = 1.0：假设每块 KV 在保留窗口内平均被完整读回一次（命中一次）；重访密集场景可按 2–3 倍上浮。
    DSA 稀疏注意力索引已计入：DeepSeek-V4.1 / GLM-5.x / Hy4 / Qwen3.8-Flash-Next 的索引状态（config 的 index_* 字段）按每 token 缓存、与 KV 同精度计入单 token KV 与卸载量——稀疏注意力省的是算力，不省这份存储。
    在途 KV 常驻 HBM 比例 = 50%（v1.6）：本工具场景即 KV 卸载，不要求全部在途 KV 驻留 HBM——显存下限、TP×PP 网格可行性与 KV 水位均只按一半在途 KV 常驻（复制后 ×50%）核算，另一半常驻卸载设备、按页脚『写带宽×保留窗口 / 在途工作集』两口径另行计量。此比例写在代码常量 KVH 中。
    KV 显存复制系数：张量并行（TP）切分注意力时，每个 TP 秩至少持有 1 个 KV 头，TP 超过 KV 头数即产生整头复制（vLLM/SGLang 标准行为）；GQA 为 ⌈TP÷KV头数⌉ 份、MLA 的单条 latent 不切分、按 TP 份复制——显存需求与水位据此放大，卸载池仍存单份。
    并行网格偏好：节点内 TP 优先、TP ≤ max(16, 每节点GPU数)、跨节点 TP 与 PP>8 会给出提示；不搜索 EP/DP 拓扑（K3 类奇数层 MLA 模型可能因此给出偏大网格）。
    decode 聚合吞吐参考 dec_agg = 350 tok/s/卡 × 实例 GPU 数 × (算力÷2.0)：350 tok/s/卡 为 H100 级 32 卡实例聚合 11,200 tok/s 的外推值【假设】；decode 是访存受限而非算力受限，此值属粗略参考，务必以实测替换。
    KV 水位阈值 70%：超过即建议扩容或降压在途（工程经验阈值）。
    容量单位口径：本页面 GB/TB 均为 10⁹/10¹² 字节；厂商标称显存若按 GiB 计，结果偏保守约 7%。
    索引器键缓存统一为 MQA 单键（v1.5）：DSA/MSA 稀疏注意力的 index 键缓存按"拥有层 × 128 维单键"计（32/64 个 index 头是查询侧概念，不复制键；拥有层数取 config 的 indexer_types(full)/sparse_attention_freq/层列表），DeepSeek-V3.2 实测口径验证（61 层全索引 → 35,136+7,808=42,944 元素/token）。MiMo-V2.6 为混合滑窗架构：9(10) 全层 + 39(60) 个 128-token 窗口层，窗口缓存转每序列快照。
    DeepSeek-V4 系 / Kimi-K3 按官方参考实现建模（v1.4）：V4.1-1017 与 V4-Flash-0731 的全局 KV 是池化压缩存储（每 1/ratio token 一条 512 维 latent：V4.1 → 2.5 条/token，0731 → 5.41 条/token）；indexer 键缓存为源层共享的 128 维单键（非 32/64 头各存）；滑窗 128×512/层 FP8 按每序列常量计入明细。Kimi-K3/K3.1 为 69 KDA 线性 + 24 MLA 混合（循环态 116.2M 元素/序列，FP32）。结构口径与 kvcache.ai 计算器一致；其 890 B/token 为官方 FP4 载荷含量化 scale（本工具选 FP4 档 ≈ 862 B，+scale ≈ 890 B）。V4 系 prefill 二次项仍按稠密上界（DSA 实际为稀疏 topk 打分，TTFT 属保守值）。
    精度默认随模型（v1.3）：权重精度默认值取自模型原生发布精度（按 HF safetensors dtype 桶与 quantization_config 判定，见模型表"原生权重"列）；KV 默认：原生 FP8 或 FP4 → FP8，BF16 → BF16。混合精度检查点（FP8 注意力 + FP4 专家，如 V4 系 / Kimi / MiMo / M3.1）在 FP4 档按全体 0.5 B/参数计，较真值低估 FP8 注意力部分约 10～25%，需保守可手动切 FP8 档。
    前缀去重率 = 0：保守口径——每个请求独立存储自己的 KV，不依赖跨请求前缀共享收益。
    线性注意力状态按 FP32：混合模型的循环状态（如 Gated DeltaNet 的矩阵状态）对量化敏感，即使 KV 选了 FP8/INT4，该部分仍按 4 B/元素计。
    Prefill 算力 2×P_active×ctx + L_full×(d_model+d_kv)×ctx²：一次项为全部激活参数的矩阵乘，二次项为全注意力层的 QKᵀV；decode 算力 2×P_active FLOPs/token。注意：二次项为工程简化式（Q 侧宽度取 hidden、且不乘标准 2×MAC 因子），较教科书完整式约低 2×，TTFT 校核相应偏乐观。

    计算链

    每实例节点数 = ⌈(权重 + 在途×单请求KV) ÷ (GPU数×显存×90%)⌉，随后沿节点数向上搜索最小合法并行网格：TP（可跨节点）须同时整除注意力头数与 hidden 维，PP 须整除层数（vLLM/SGLang 均要求整除；TP 超过 KV 头数时 KV 头复制存放） → 实例数 = ⌊节点总数 ÷ 每实例节点数⌋； 到达率 = 实例数×在途 ÷ 单请求服务时长；写带宽 = 到达率×单请求KV；容量（双口径并列）= 保留窗口制：写带宽×窗口×1.2（页面主 KPI，选型决策）｜ 在途工作集制：在途实例×在途×单请求KV×1.2（明细行，不假设保留期）；显存足迹按 TP 复制系数放大（GQA：⌈TP/KV头⌉，MLA：TP）。
