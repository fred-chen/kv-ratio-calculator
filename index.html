    固定假设（不可调，均已计入公式）

    算力基准："单 GPU 算力"填矩阵乘实际执行精度的稠密（非稀疏）峰值——BF16 权重按 BF16 档、FP8 权重按 FP8 档、INT4（weight-only，主流方案，反量化后用 BF16 算）按 BF16 档；厂商标称的"稀疏翻倍"数字不可用。默认 2.0 PF = H100/H200 的 FP8 稠密峰值（1979 TFLOPS），与报告基线一致。
    算力有效利用率 MFU = 50%：标称 PFLOPS 是峰值，推理中注意力/通信/访存开销后实际约一半能被有效计算利用，业界大模型推理常用取值。
    显存利用率 = 90%：单卡显存中可安全用于"权重 + KV"的比例，余 10% 给激活值、框架缓存与碎片。
    容量冗余系数 = 1.2：卸载设备容量按需求上浮 20%，覆盖元数据、EC 对齐与突发。
    读放大系数 = 1.0：假设每块 KV 在保留窗口内平均被完整读回一次（命中一次）；重访密集场景可按 2–3 倍上浮。
    DSA 稀疏注意力索引已计入：DeepSeek-V4.1 / GLM-5.x / Hy4 / Qwen3.8-Flash-Next 的索引状态（config 的 index_* 字段）按每 token 缓存、与 KV 同精度计入单 token KV 与卸载量——稀疏注意力省的是算力，不省这份存储。
    前缀去重率 = 0：保守口径——每个请求独立存储自己的 KV，不依赖跨请求前缀共享收益。
    线性注意力状态按 FP32：混合模型的循环状态（如 Gated DeltaNet 的矩阵状态）对量化敏感，即使 KV 选了 FP8/INT4，该部分仍按 4 B/元素计。
    Prefill 算力 2×P_active×ctx + L_full×(d_model+d_kv)×ctx²：一次项为全部激活参数的矩阵乘，二次项为全注意力层的 QKᵀV；decode 算力 2×P_active FLOPs/token。

    计算链

    每实例节点数 = ⌈(权重 + 在途×单请求KV) ÷ (GPU数×显存×90%)⌉，随后沿节点数向上搜索最小合法并行网格：TP（可跨节点）须同时整除注意力头数与 hidden 维，PP 须整除层数（vLLM/SGLang 均要求整除；TP 超过 KV 头数时 KV 头复制存放） → 实例数 = ⌊节点总数 ÷ 每实例节点数⌋； 到达率 = 实例数×在途 ÷ 单请求服务时长；写带宽 = 到达率×单请求KV；容量 = 写带宽×保留窗口×1.2。
